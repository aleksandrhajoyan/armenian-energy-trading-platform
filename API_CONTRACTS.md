# API Contracts

HTTP API design principles for the FastAPI surface. Only endpoints listed as **implemented** are live.

## Status

| Item | State |
| --- | --- |
| Runtime API | FastAPI app factory (`create_app`) with correlation middleware, request logging, and centralized exception translation |
| Routers | Health router under `/api/v1` |
| OpenAPI schema | Generated by FastAPI at runtime; not a published contract file |
| Endpoints | `GET /api/v1/health` implemented; remaining business endpoints **TBD** |
| Error envelope | Implemented for all HTTP errors produced by this application |
| Correlation ID | Implemented via `X-Correlation-ID` |

## Design principles

- The API is a **transport adapter**. Business logic lives in application use cases, not in routers.
- Request and response bodies use **canonical contracts** (or thin HTTP wrappers around them). Vendor CSV/Excel/PDF shapes must not appear on the public API.
- Routers call use cases / the Chief Orchestrator Agent port. They do not import infrastructure adapters or ML trainers.
- The API / composition root wires implementations into application ports. It does not contain market formulas.
- Idempotency for workflow-triggering commands will be defined when those endpoints exist.
- Authentication/authorization model is **TBD** (not specified in this chunk).

## Versioning

- Public HTTP routes are prefixed with `/api/v1`.
- Breaking changes require a new version prefix. Additive optional fields on canonical contracts should remain backward compatible.
- Internal Python module layout is independent of the URL version.

## Canonical request / response

- Successful JSON responses wrap or directly serialize canonical Pydantic models defined in the domain (implementation in later chunks), or thin HTTP-specific models such as health.
- Collection responses should include stable pagination fields when lists are introduced (schema TBD).
- Clients never send raw Armenian-header tables to domain endpoints; upload/ingest endpoints, if added, terminate in infrastructure adapters.

## Standard error envelope (implemented)

Every error response uses:

```json
{
  "error": {
    "code": "resource_not_found",
    "message": "Resource was not found.",
    "correlation_id": "portfolio-demo-123"
  }
}
```

| Field | Meaning |
| --- | --- |
| `error.code` | Stable machine-readable code |
| `error.message` | Safe human-readable message. Never a traceback, exception repr, SQL, credential, request body, or environment value. |
| `error.correlation_id` | Request correlation ID. Always present. Matches `X-Correlation-ID`. |
| `error.details` | Optional sanitized validation details. Omitted when not applicable. |

Validation failures may include sanitized details:

```json
{
  "error": {
    "code": "request_validation_error",
    "message": "Request validation failed.",
    "correlation_id": "...",
    "details": [
      {
        "field": "query.limit",
        "message": "Input should be greater than 0",
        "type": "greater_than"
      }
    ]
  }
}
```

`details[].field`, `details[].message`, and `details[].type` are the only public validation fields. Pydantic/FastAPI raw `input` values are **omitted**.

Unexpected exception internals are **never** exposed: no traceback, exception class name, module path, or `str(exc)`.

### HTTP mappings

| Source | HTTP | `error.code` |
| --- | --- | --- |
| `InvalidRequestError` | 400 | `invalid_request` |
| `ResourceNotFoundError` | 404 | `resource_not_found` |
| `ConflictError` | 409 | `conflict` |
| `DependencyUnavailableError` | 503 | `dependency_unavailable` |
| FastAPI `RequestValidationError` | 422 | `request_validation_error` |
| Unknown route / Starlette HTTP 404 | 404 | `not_found` |
| Unhandled exception | 500 | `internal_error` |

Only the four explicitly mapped `ApplicationError` subclasses receive 4xx/503 responses. Bare `ApplicationError` and any subclass that has not been added to the API mapping fail closed to sanitized HTTP 500 (`internal_error`) with the generic public message. Incomplete API translation configuration is never presented as a client error. The original application message and unmapped error code stay in internal logs only.

HTTP mapping lives only in the API layer. Application errors do not carry status codes.

The public 500 message is always:

```text
An unexpected internal error occurred.
```

## Correlation ID

- Header name: `X-Correlation-ID`.
- If the caller supplies a valid ID, it is reused on the response header and in error bodies and structured logs.
- If the header is missing or invalid, the server generates a UUID-based ID. The request is **not** rejected solely because the header is unsafe.
- Acceptance rules for incoming IDs: non-empty; at most 128 characters; ASCII letters, digits, `.`, `_`, `:`, `-`.
- The health endpoint does not add a correlation field to its JSON body. The response header is still set.

## Endpoints

### `GET /api/v1/health` (implemented)

Process/application liveness for this FastAPI process only.

| | |
| --- | --- |
| **Purpose** | Confirm that the HTTP application is serving. Used by local development and later process probes. |
| **Auth** | None |
| **Request body** | None |
| **Side effects** | None. Does not open database, Redis, Qdrant, ML, LLM, or external connections. |
| **Headers** | Response includes `X-Correlation-ID`. |

**HTTP 200** JSON body:

| Field | Type | Meaning |
| --- | --- | --- |
| `status` | `"ok"` | This process is serving HTTP. |
| `service` | string | Configured application name (`APP_NAME`). |
| `environment` | `"development"` \| `"test"` \| `"production"` | Configured application environment (`APP_ENV`). |

This is **not** an infrastructure readiness check. A 200 response does **not** mean PostgreSQL, TimescaleDB, Redis, Qdrant, LangGraph, ML models, or any external service is healthy. Those systems are not implemented.

Candidate families still unspecified until later chunks (Phase 9 and any explicitly scoped earlier slice):

- Readiness (when infrastructure exists)
- Workflow start / status (Chief Orchestrator Agent)
- Canonical reads (forecasts, bids, settlements)
- Ingest triggers (files) — must land on adapters, not agents
